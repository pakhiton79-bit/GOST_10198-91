# Расчёт ящика — ГОСТ 10198-91

Производственные калькуляторы — однофайловый HTML (расчёт + печатная
спецификация + чертежи расположения деталей на фото). Три итоговых файла:

- `dist/GOST10198_91POLOZIA.html` — тип I-3, крепление груза за полозья.
- `dist/GOST10198_91DOSKI_DNA.html` — тип I-3, крепление груза к доскам дна
  (та же вёрстка и расчёт, что и POLOZIA, отличается только толщина доски
  дна — по Таблице 4 п.1.6.9, а не по новому правилу).
- `dist/GOST10198_91_I1.html` — тип I-1, полностью независимая методика
  (другая конструкция щитов). Чертежи пока заглушки — фото ещё не пришли.

Все три редактировать напрямую не нужно: собираются из `src/`.

## Структура

Общее для всех трёх файлов:

- `src/style.css` — вся CSS-вёрстка (тема, формы, таблицы, печать).
- `src/common-print.js` — механика печати: подгонка под один лист А4
  (`fitPrintAreaToOnePage`), резерв места под вылет подписей чертежей
  (`reserveDiagramOverflow`, `reserveDiagramOverflowScreen`), масштабирование
  чертежей (`applyDiagramWidths`), запуск печати (`printBox`). Одинакова для
  обоих типов — расходится только `buildPrintHtml()` (содержимое печатной
  страницы), которая остаётся в каждом типе своя.

Тип I-3 (`GOST10198_91POLOZIA.html` / `GOST10198_91DOSKI_DNA.html`):

- `src/calc.src.html` — HTML-каркас (разметка форм, таблиц, дропдаунов), ~190
  строк, с плейсхолдерами `/*__STYLE_CSS__*/`, `/*__LOGIC_JS__*/`,
  `/*__DIAGRAMS_JS__*/`, `/*__COMMON_PRINT_JS__*/`, `/*__APP_JS__*/`.
- `src/logic.js` — чистые расчётные формулы ГОСТ (толщины, сечения полозьев,
  Таблица 19, Таблица 4 и т.п.) — без обращений к DOM. Правки формул/таблиц
  ГОСТ — сюда.
- `src/diagrams.js` — константы картинок (`*_IMG_B64`, плейсхолдеры вида
  `__IMG:dno.png__`) и все функции `diagram*()`, рисующие чертёж поверх фото
  (SVG-стрелки + подписи). Добавление/правка чертежа — сюда.
- `src/app.js` — UI (фильтр толщин, тип крепления), сама `calculate()` и
  `buildPrintHtml()`. Содержит один плейсхолдер `/*__FLOOR_BOARD_CALC__*/` —
  здесь расходятся два итоговых файла (см. `src/variants/`).
- `src/variants/floor_board_new.js` — толщина доски дна по новому правилу
  (для GOST10198_91POLOZIA.html).
- `src/variants/floor_board_table4.js` — толщина доски дна по Таблице 4
  (для GOST10198_91DOSKI_DNA.html).

Тип I-1 (`GOST10198_91_I1.html`), независимая методика от типа I-3:

- `src/i1/shell.html` — свой HTML-каркас с плейсхолдерами `/*__STYLE_CSS__*/`,
  `/*__LOGIC_JS__*/`, `/*__DIAGRAMS_JS__*/`, `/*__COMMON_PRINT_JS__*/`,
  `/*__UI_JS__*/`, `/*__CALC_JS__*/`.
- `src/i1/logic.js` — расчётные формулы этого типа (толщина по плотности
  упаковывания груза, количество планок и т.п.).
- `src/i1/diagrams.js` — пока только заглушки (`diagramPlaceholder`) — фото
  чертежей для этого типа ещё не пришли.
- `src/i1/ui.js` — фильтр толщин «в наличии» и галочка «Полоз нужен».
- `src/i1/calc.js` — `calculate()` и `buildPrintHtml()`.

Плюс:

- `src/images/*` — сами картинки чертежей (PNG/JPG), отдельными файлами.
- `build.py` — собирает всё перечисленное выше + `src/images/*` в три готовых
  файла (подставляет содержимое файлов вместо плейсхолдеров, заменяет
  `__IMG:...__` на base64).

## Сборка

```
python3 build.py
```

Результат — три самодостаточных файла в `dist/` (можно открывать локально в
браузере без интернета, кроме шрифта Google Fonts).

## Зачем так

Единый HTML-файл с картинками в base64 — это 1+ МБ текста в одной строке на
картинку, поэтому картинки вынесены в `src/images/*` отдельными файлами.
Дополнительно сам код каждого типа разбит по темам (вёрстка/CSS, чистые
формулы ГОСТ, чертежи, UI, расчёт) вместо одного файла на 2500+ строк — так
типичная правка (один чертёж, одна формула ГОСТ) требует читать только
небольшой профильный файл, а не весь калькулятор целиком. То, что действительно
общее между всеми файлами (`style.css`, `common-print.js`), лежит в одном
экземпляре и не дублируется; то, что расходится (формулы, вёрстка форм,
чертежи), — в файлах своего типа. Внутри типа I-3 два итоговых файла
дополнительно расходятся только в одном маленьком файле-варианте
(`src/variants/floor_board_*.js`), а не дублируют друг друга целиком.
Финальная склейка в единые файлы — чисто механическая, без модели.

## Добавление нового чертежа

1. Добавить файл картинки в `src/images/` (для типа I-1 — в `src/i1/` или
   `src/images/`, план тот же).
2. В `diagrams.js` соответствующего типа добавить константу вида
   `const XXX_IMG_B64 = "data:image/png;base64,__IMG:xxx.png__";`.
3. Там же добавить функцию `diagramXxx()` с массивом `records` (координаты
   стрелок/подписей в пиксельных координатах картинки) — см. соседние функции
   (`diagramDno`, `diagramKryshka` и т.д.) как образец.
4. Пересобрать: `python3 build.py`.
