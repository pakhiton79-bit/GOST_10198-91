# Расчёт ящика — ГОСТ 10198-91

Производственные калькуляторы — однофайловый HTML (расчёт + печатная
спецификация + чертежи расположения деталей на фото). Три калькулятора плюс
стартовая страница со ссылками на них:

- `docs/index.html` — стартовая страница (список ГОСТов и типов тары).
- `docs/GOST10198_91POLOZIA.html` — тип I-3 (крепление груза за полозья или
  к доскам дна — переключатель на странице).
- `docs/GOST10198_91_I1.html` — тип I-1, полностью независимая методика
  (другая конструкция щитов). Чертежи пока заглушки — фото ещё не пришли.

Ни один из них редактировать напрямую не нужно: все собираются из `src/`.

Папка называется `docs`, а не `dist` — так её можно напрямую указать
источником в настройках GitHub Pages (Settings → Pages → Source: Deploy
from a branch → папка `/docs`).

## Структура

Общее для всех трёх файлов:

- `src/style.css` — вся CSS-вёрстка (тема, формы, таблицы, печать).
- `src/common-calc-state.js` — статусы расчёта у кнопок, кнопка «Рассчитать»
  (`calculate`), устаревание результата при изменении параметров, отказы и
  подсказки.
- `src/common-table-edits.js` — ручные правки таблицы деталей
  (`readTableEdits`, `applyTableEdits`).
- `src/common-diagram-fit.js` — подгонка чертежей под слот с учётом вылета
  подписей: на экране (`fitDiagramsOnScreen`) и в печати
  (`fitDiagramsForPrint`).
- `src/common-print.js` — печать и PDF: подгонка под один лист А4
  (`fitPrintAreaToOnePage`), масштабирование чертежей (`applyDiagramWidths`),
  запуск печати (`printBox`), «Скачать PDF» (`downloadPdf`). Содержимое
  печатной страницы (`buildPrintHtml()`) у каждого типа своё.
- `src/common-settings.js` — шестерёнка общих настроек вверху каждой
  страницы (пока — тема: светлая/тёмная, по умолчанию светлая); встраивается
  в `<head>` всех страниц, чтобы тема ставилась до отрисовки.

Тип I-3 (`GOST10198_91POLOZIA.html`, крепление за полозья / к доскам дна —
переключатель на самой странице). Файлы разложены так же, как в gost_backend
(`compute/` — как `backend/src/i3`, остальное — как `frontend/public/js/i3`):

- `src/i3/shell.html` — HTML-каркас с плейсхолдером на каждый файл (список —
  `I3_PARTS` в `build.py`).
- `src/i3/compute/` — расчёт (без обращений к DOM):
  - `compute.js` — расчёт по шагам (`computeGost10198I3`);
  - `dno.js`, `kryshka.js`, `end-panel.js`, `bokovoy.js` — узлы ящика;
  - `plank-layout.js` — раскладка поясов планок (штатная / число / зазор);
  - `sections.js`, `data/table19.js`, `data/table4.js`, `data/table14.js` —
    формулы и таблицы ГОСТ (правки формул/таблиц — сюда);
  - `helpers.js` — `fillBoards`, `vol`, `roundup` и т.п.
- `src/i3/options.js` — толщины «в наличии», способ крепления, запоминание галочек.
- `src/i3/plank-layout.js` — ручная настройка поясов планок (как у I-1).
- `src/i3/beams.js` — ручная настройка поперечных брусьев крышки.
- `src/i3/calc-i3.js` — входные данные, расчёт, подсветка ошибок.
- `src/i3/render-i3.js` — вывод результата: итог, таблицы, чертежи, предупреждения.
- `src/i3/print-i3.js` — содержимое печати/PDF.
- `src/i3/diagrams/` — чертежи по узлам (фото, генерируемый вариант и выбор
  между ними — в одном файле): `generated.js` (общие функции генерируемых

Плюс:

- `src/images/*` — сами картинки чертежей (PNG/JPG), отдельными файлами.
- `build.py` — собирает всё перечисленное выше + `src/images/*` в три готовых
  файла (подставляет содержимое файлов вместо плейсхолдеров, заменяет
  `__IMG:...__` на base64).

## Сборка

```
python3 build.py
```

Результат — стартовая страница и три самодостаточных файла калькуляторов
в `docs/` (можно открывать локально в браузере без интернета, кроме шрифта
Google Fonts).

## Зачем так

Единый HTML-файл с картинками в base64 — это 1+ МБ текста в одной строке на
картинку, поэтому картинки вынесены в `src/images/*` отдельными файлами.
Дополнительно сам код каждого типа разбит по темам (вёрстка/CSS, чистые
формулы ГОСТ, чертежи, UI, расчёт) вместо одного файла на 2500+ строк — так
типичная правка (один чертёж, одна формула ГОСТ) требует читать только
небольшой профильный файл, а не весь калькулятор целиком. То, что действительно
общее между всеми файлами (`style.css`, `common-*.js`), лежит в одном
экземпляре и не дублируется; то, что расходится (формулы, вёрстка форм,
чертежи), — в файлах своего типа. Внутри типа I-3 два итоговых файла
дополнительно расходятся только в одном маленьком файле-варианте
(`src/variants/floor_board_*.js`), а не дублируют друг друга целиком.
Финальная склейка в единые файлы — чисто механическая, без модели.

## Добавление нового чертежа

1. Добавить файл картинки в `src/images/` (для типа I-1 — в `src/i1/` или
   `src/images/`, план тот же).
2. В `diagrams.js` соответствующего типа добавить константу вида
   `const XXX_IMG_B64 = "data:image/png;base64,__IMG:xxx.png__";`.
3. Там же добавить функцию `diagramXxx()` с массивом `records` (координаты
   стрелок/подписей в пиксельных координатах картинки) — см. соседние функции
   (`diagramDno`, `diagramKryshka` и т.д.) как образец.
4. Пересобрать: `python3 build.py`.

## Картинки дна по числу полозьев

Чертёж «Дно» (I-3 и II-1) на 3-8 полозьев - это фото на 2 полоза с
дорисованными торцами средних полозьев: `src/images/dno_3skids.png` ...
`dno_8skids.png`. Их делает `tools/make_dno_images.py` из
`src/images/dno_ii1.jpg`: `python3 tools/make_dno_images.py src/images/dno_ii1.jpg src/images`.
